# 数据定义

## 变更文件

CSV 采用逗号和双引号，列顺序可变。整文件优先 UTF-8（含 BOM），回退 GB18030。每份收件按原字节 SHA-256 标识，最多 2 MiB 与 5000 条表头后记录。解析按逻辑记录迭代，记录物理起始行。零字节、仅空白、只有表头、断引号分别返回错误。单行列数错误、字段失效等行级问题隔离，其余继续。

| 字段 | 类型与规则 |
|---|---|
| `event_id` / `invoice_id` / `customer_id` | 不透明标识，保留前导零，1–64 位 ASCII 字母、数字、下划线、点和连字符 |
| `kind` | `VERSION`、`PAYMENT`、`REVERSAL` |
| `effective` | 有效始日或变动业务日，`YYYY-MM-DD` |
| `valid_to` | 版本独有，排除终日，空值表示无终点 |
| `known` | 有时区的 ISO 时间，精确到微秒；以 UTC 归一；工作台显示固定 UTC+08:00 |
| `due` | 版本必填，过期起算基准日 |
| `amount_cny` | 正金额，人民币元。空白、`-`、`N/A`、`NULL`、`未知` 为缺失；零值按无效金额隔离。支持全角和正确千分组；Decimal 转整数分后计算 |
| `ref` | 初版留空。修订版引用当前知识版本；收款或冲销引用已采信的原账面版本 |
| `note` | 原始备注，可含换行 |

同事件编号且同 UTC 知悉时刻的规范化副本只采信最早物理行；内容矛盾时隔离该时刻所有规范化候选。以后重复占用某个已可见事件编号时，仅隔离后来事件；历史截面保持原样。重复、空白、重复表头独立计数。

## 两个时间条件

- 版本业务区间 `[effective, valid_to)`；收款与冲销业务日 `<=` 有效切点。所有可见事件必须同时满足 `known <=` 知悉切点。
- 维持每张发票一位客户。分段版本可接续，新分段与已有有效区间冲突时保留已采信版本，同知悉时刻冲突的新分段同时隔离。显式修订只替换同发票、客户和业务区间的父版。父版的知悉区间在修订的知悉时刻排他结束；同刻多个候选亲缘修订都隔离。
- 收款和冲销在所选知识下从头按业务日、知悉时刻、类型、事件编号排序。原票未可见时进入待补，之后原票可见便可重算。允许引用已替换原版，原版须匹配发票和客户并且开始日不晚于变动日。变动当日和截面均需存在有效版本。可冲减上限为当日面额与截面面额的较小值减之前采信变动，超额整笔隔离。
- 同一发票的相邻版本描述累计债务池；采信的冲减在相邻有效版之间连续。没有活动版本的期末截面不显示该发票的余额；相关历史变动可在 `inactive` 中查看。

## 对账与归档

- 收件输入等于采信、解析隔离、重复、空白、重复表头之和。版本和业务隔离及待补是各个截面的裁决结果，单独统计。
- 逾期天数按业务有效日减到期日。到期当日仍未逾期。五桶为未逾期、1–30、31–60、61–90、91 天以上，已结清记录不入桶。
- 期间使用三次截面：期初、期初有效日与期末知悉截止、期末。第一步差为迟报回补。固定回补后余额按期末到期日迁移到期末桶，再记本期净变动；已退出发票按回补后到期日迁移后退场。迁移净额为零。
- 期初余额加面额净变动、减收款和冲销净变动，得到期末余额。各账龄桶按期初、迟报、迁移、本期到期末勾稽。入账净变动包含版本面额调整、新增和退出；有退出时面额、历史收款或冲销净变动可为负数。
- 归档编号取来源 SHA-256、规则版本与 UTC 化期间参数的摘要。在一个 SQLite 事务中提交清单、摘要和证据。重跑使用原始来源重新计算，逐字节校验且复用原归档。导出可复核来源隔离、各截面、逐票变化和账龄聚合。

## 折扣结算（M8）

折扣结算复用应收来源的原票版本册，另接收两条独立来源，各自按原字节 SHA-256 标识并整字节留存，不覆盖、不丢失。

### 条款版本流 `term`

| 字段 | 类型与规则 |
|---|---|
| `term_id` / `invoice_id` / `customer_id` | 与收件相同的不透明标识规则 |
| `effective` | 折扣窗口起算日，`YYYY-MM-DD` |
| `known` | 条款到达（知悉）时刻，带时区；修订条款次日才到则不参与此前回单 |
| `discount_rate` | 百分比，`0.01–100.00`，两位小数；内部转基点（2.00 → 200bp） |
| `discount_window_days` | 折扣窗口天数，正整数，含起算日与截止日（闭区间） |
| `ref` | 初版留空；修订引用当前已知的父条款，缺父版或发票/客户不匹配则隔离 |

每张发票只允许一条初版条款（重复初版按 `TERM_ROOT_CONFLICT` 隔离）；同一父版在同一知悉时刻出现多个修订按 `TERM_FORK` 一起隔离，条款停留在父版。条款按知悉轴串成版本链，回单只取 `term.known <= 回单知悉时刻` 的最新条款，因此修订不追溯改写已关账期间的净额。

### 收款回流 `receipt`

| 字段 | 类型与规则 |
|---|---|
| `receipt_id` / `invoice_id` / `customer_id` | 不透明标识，保留前导零 |
| `pay_date` | 客户付款业务日；窗口判定用业务日而非录入日 |
| `known` | 回单录进系统的知悉时刻，月末后补录也以该时刻为准 |
| `paid_cny` | 实收金额，正金额，转整数分 |
| `ref` | 必填，引用应收来源中已采信的原票版本，校验同发票同客户 |

### 结算裁决

- 回单按付款日、知悉时刻、编号排序，只取 `known <=` 结算知悉切点者；引用原票不可见为 `TERM_TARGET_PENDING`，引用非版本为 `TERM_TARGET_INVALID`，发票/客户不符为 `TERM_TARGET_SCOPE`，付款日无活动版本为 `NO_ACTIVE_VERSION`。
- 折扣金额 `ROUND_HALF_UP(票面分 × 基点 / 10000)`，净应收 = 票面 − 折扣。窗口为 `[effective, effective + window_days]` 闭区间。
- 回单知悉时无条款、或付款日落在窗口外：不享折扣，实收须等于票面，否则 `DISCOUNT_MISMATCH`。
- 窗口内实收正好等于净应收才确认折扣；按票面全额付款为 `DISCOUNT_WINDOW_MISS`，低于票面的部分回款为 `DISCOUNT_PARTIAL`，其它对不上为 `DISCOUNT_MISMATCH`；超过可冲减余额为 `EXCEEDS_BALANCE`。
- 任一回单进入隔离即整批 `HELD`，`POST /api/settlement/publish` 返回 409 `SETTLEMENT_HELD` 且不写任何结算行；全部可解释才 `PUBLISHABLE`。
- 工作台按发票汇总票面 `face_cents`、折扣 `discount_cents`、净额 `net_settled_cents` 与未收 `outstanding_cents`，逐张回单保留回单、原票、采用条款与窗口证据。
- 结算编号取三份来源 SHA-256、规则版本与 UTC 知悉切点的摘要，在一个事务内提交。重跑同一批回单命中同一编号并 `ON CONFLICT DO NOTHING`，不新增结算；写入中断回滚，旧版折扣快照原样保留。导出证据含来源标识、裁决、隔离与摘要，逐字节可复核。

当前适用于人民币、单文件来源和单一结算时区。多币种、时区自动推断、旧规则可执行包与变更流跨文件合并不在范围内。
